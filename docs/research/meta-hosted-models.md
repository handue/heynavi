# meta-hosted-models

## SUMMARY
The old "Llama API" is gone. Meta's hosted developer API is now called the Meta Model API. Its docs are at dev.meta.ai/docs; the old domains llama.developer.meta.com and ai.developer.meta.com/docs both redirect there. The base URL is https://api.meta.ai/v1 and auth is `Authorization: Bearer $MODEL_API_KEY`. It speaks OpenAI Chat Completions, OpenAI Responses and Anthropic Messages, and Meta has no SDK of its own: you use `pip install openai` with base_url set. Hosted models are: muse-spark-1.3 (recommended), muse-spark-1.2, muse-spark-1.1, two cheap contributor-tier variants (`-contributor`), muse-wonder-1.0 (preview, expensive), muse-image-1.0, muse-voice-transcribe-1.0 and sam-3.1. Muse Spark Open (816B MoE) and Muse Glimmer (30B) are open-weight only and not on the Model API. No Llama 4 model is listed. For HeyNavi: Muse Spark takes base64 JPEGs (up to 50 per request) and returns structured JSON via `response_format` `json_schema`. It also has documented object grounding on a normalized 0-1000 grid, which gives you a box and left/right position directly. SAM 3.1 takes a noun phrase plus an image, returns boxes, masks and optional confidence for $0.0025 per image, and returns nothing when there is no match. Muse Voice Transcribe has realtime WebSocket and REST endpoints, costs $0.18/hour and supports Korean. No text-to-speech endpoint was found, so use on-device iOS TTS. The biggest risk is latency. Muse Spark always reasons (`minimal` is the lowest setting; `none` returns HTTP 400). Every public latency figure is for xhigh/max effort or of unclear origin, ranging from about 1.25 s to 44 s, so the <2 s per-frame target is unverified and must be measured on day one. The $150 hackathon credit appears only in secondary sources; Meta itself says only "free Model API credits", and how to claim them is not documented publicly.

## RECOMMENDATION
Backend client: from FastAPI, use the `openai` Python SDK with `AsyncOpenAI(base_url="https://api.meta.ai/v1", api_key=os.environ["MODEL_API_KEY"])` and Chat Completions. Pydantic models go to `client.beta.chat.completions.parse()` (or to `response_format` `json_schema` with `strict: true`). Use plain `httpx` for SAM 3.1 (Responses endpoint) and for the voice REST endpoint. Keep the key server-side only, and skip `llama-api-client`.

First thing to do (day 1): run `GET /v1/models` to confirm which IDs the team can use. Then time 20 calls each of muse-spark-1.3 at `reasoning_effort="minimal"` (one ~640-768px JPEG, short JSON schema, `max_completion_tokens` about 512), muse-spark-1.3-contributor, and sam-3.1. Every published latency figure is for high effort, so this measurement decides the design.

(a) Per-frame object search and position:
- First choice: sam-3.1 as the per-frame detector. Send the noun phrase from the goal (e.g. "chair") plus the frame, with `metadata.include_confidence:"true"` and `mask_encoding:"one_bit"`.
- An empty `output_text` means not found. A box gives you left/center/right directly from x-center against w, with no reasoning delay.
- Cost: $0.0025 per frame, so about 6,000 frames (around 2.5 hours of looping at 1 frame per 1.5 s) costs about $15.
- Confirm across 2-3 frames in a row with confidence above a threshold before speaking.
- Use muse-spark-1.3 (Standard, minimal effort) only when you need wording or a second check, e.g. "is it the user's chair, any obstacle nearby?". Ask for the documented grounding JSON: bbox on the 0-1000 grid, `found` boolean, `position` enum left/center/right, short description.
- Fallback 1: if SAM latency or the Korean-to-English noun mapping is a problem, run muse-spark-1.3 minimal alone with the grounding schema.
- Fallback 2: if Spark minimal is over 2 s, run requests back to back with one in flight at a time, never queued. Downscale frames to about 512px at JPEG q≈0.6, and put the fixed developer prompt first so automatic prompt caching applies.
- Scene description on request: muse-spark-1.3 at minimal or low effort, streamed, so the client can start TTS on the first sentence.

(b) OCR and sign reading: muse-spark-1.3, `reasoning_effort="low"`, one higher-resolution frame (about 1280px, roughly 1,500 tokens, about $0.002), streamed. Fall back to muse-spark-1.2 if 1.3 behaves badly.

(c) Voice-command intent parsing:
- First, a deterministic keyword/regex parser on the backend for the core commands in English and Korean: find X, stop, describe, read, faster/slower. This answers instantly at no cost.
- Fall back to muse-spark-1.3 minimal with a small strict `json_schema` (intent enum, target noun phrase normalized to English for SAM, language). Function tools would also work, but tool_choice only supports "auto", so JSON schema is the safer route.
- Contributor-mode models cost about 12x less, but Meta may train on the data. Use them only for synthetic or dev traffic, never for real users' camera frames or voice, and say so in the submission if you use them.

(d) Speech-to-text: muse-voice-transcribe-1.0 at $0.18/hour, which is negligible.
- Simplest path in 6 days: record a short mono 16 kHz 16-bit WAV clip on the phone (push-to-talk), upload it to FastAPI, and POST it to /v1/asr/transcribe with `languageBias` ["English","Korean"] and keywords set to common object names.
- Better path: stream PCM from the phone through the backend to wss://api.meta.ai/v1/asr/realtime in ENDPOINTING mode with `partialMode` CUMULATIVE. This needs raw PCM capture in Expo. As a further fallback, use on-device iOS speech recognition.

Text-to-speech: Meta has no TTS endpoint, so use on-device iOS TTS (e.g. expo-speech with ko-KR/en-US voices and rate control) and implement barge-in locally.

Avoid muse-wonder-1.0 for the realtime loop: it costs $4/$20 per 1M tokens and has high reported TTFT. Llama 4 is not on the API. Muse Spark Open and Muse Glimmer would need third-party hosting or self-hosting, so treat them only as emergency fallbacks if you have Fireworks, Baseten or Modal credits.

Budget: about $15 for SAM, $10-25 for Spark calls and under $1 for STT keeps development plus demo well under $150. Cap `max_completion_tokens`, since reasoning tokens are billed as output.

## RISKS
- Latency is unverified. Muse Spark always reasons and cannot be set to 'none'. Every published TTFT is at xhigh/max effort (25-44 s) or of unclear origin (1.25-3.7 s), so per-frame Muse Spark calls may exceed the 2 s budget even at 'minimal'.
- SAM 3.1 has no published latency or maximum image size, and it returns masks along with boxes (there is no documented boxes-only option), so payload size and parse time need measuring.
- SAM 3.1 takes one concept per request as a noun phrase. Korean goals ('의자 찾아줘') must be turned into an English noun phrase first, which adds an intent-parsing step to the search loop.
- Reasoning tokens are billed as output and count toward max_completion_tokens. Uncapped requests can cost more than expected or have their visible JSON cut off.
- Contributor-tier models are much cheaper, but Meta may use the prompts and images to train future models. That is a privacy problem for blind users' home camera frames and voice.
- The $150 credit amount and how to claim it are not confirmed by a primary source. Billing is postpaid to a payment method, so the account may need a card on file, and credits might not cover every model (SAM, Voice, Contributor).
- Muse Voice Transcribe realtime needs raw 16/24 kHz s16le PCM over a WebSocket with the key in the handshake. Streaming that from Expo on iPhone, without exposing the key, needs native PCM capture and a backend relay. The batch WAV path is simpler but slower.
- The Meta Model API has no TTS, so spoken output and barge-in rely entirely on on-device iOS speech synthesis.
- Model IDs change often (1.1 to 1.2 to 1.3 between July and September 2026). Hard-coded IDs could break; read them from config and check GET /v1/models.
- Availability depends on country and billing support. If the developer's billing country is unsupported, access may be blocked.

## VERIFIER MISSED
- Independent low-effort latency data exists and is bad. Roboflow's Vision Evals measure Muse Spark 1.3 at LOW effort averaging about 25.8 s per object-detection sample, 14.5 s for identification and 26.7 s for OCR (https://playground.roboflow.com/models/meta/muse-spark-1-3). Muse Spark cannot be in the 1-2 s per-frame loop, even as a fallback. Treat scene description and OCR as 10-30 s background tasks, give immediate spoken feedback ("Looking..."), and stream.
- Muse Wonder and Muse Wonder Full are not available in South Korea (https://dev.meta.ai/docs/models.md). Muse Spark, SAM and Voice are not listed as restricted, but availability must be confirmed with GET /v1/models from the developer's own account and country.
- On the Responses API, store defaults to true. SAM 3.1 runs only on /v1/responses, so every camera frame from a blind user's home would be stored server-side by default, with no published retention period. Large inline base64 with store=true can also return 413 even when inference succeeds. Send store:false on every SAM and Responses call (https://dev.meta.ai/docs/protocols/responses.md, https://dev.meta.ai/docs/error-handling.md).
- Realtime ASR pacing rules: audio must arrive at about real time, never more than about 5 s ahead. Streams slower than real time are rejected with close code 1008, and a live source must keep sending PCM silence. No ephemeral or client tokens exist, and the docs say to keep keys out of mobile code. A realtime path therefore needs a continuous PCM relay from the phone through FastAPI, which raises the cost of the 'better path' a lot. The docs recommend ENDPOINTING (not PUSH_TO_TALK) for low-latency voice commands (https://dev.meta.ai/docs/speech-to-text.md).
- SAM 3.1 accepts short MP4/MOV video (H.264) with built-in object tracking, at $0.20 per 1,000 frames and a 50-frame minimum ($0.01 per clip). This is an alternative to per-frame image calls when confirming across frames: send a 2-3 s clip and get tracked boxes for every frame. Latency is unmeasured (https://dev.meta.ai/docs/sam/segmenting.md).
- Media that fails Meta's content policy returns HTTP 400 `content_policy_violation`. Non-streaming requests hit an unpublished server time limit (504, do not retry unchanged), and 503 carries Retry-After of 60 s on overload. The loop needs explicit handling for each so it never goes silent on a blind user (https://dev.meta.ai/docs/error-handling.md).
- Library versions as of 2026-10-29: openai 3.41.0 (canonical `client.chat.completions.parse`), pydantic 2.14.2 with pydantic-core 2.50.2 (cp314 wheels), fastapi 0.162.0, and meta-sam-parser 0.1.0, all compatible with Python 3.14 (PyPI JSON). @meta-sam/parser 0.1.0 is ESM-only with Node engine constraints and undocumented React Native support, so parse SAM output on the backend.
- The hosted fallbacks the researcher suggested are mostly impractical. Muse Spark Open on Groq is Enterprise-only limited preview. Muse Glimmer on Fireworks is on-demand only (no serverless) and is itself a reasoning model with no off switch. Only Muse Spark Open on Fireworks serverless (US-only, same price as Spark Standard) is readily usable, and Roboflow puts it at about 7.4 s per vision sample.
- The Indie track is judged on 'creativity, technical ambition, and whether it works', and the event page lists Muse Spark, Muse Image and SAM 3.1 as the encouraged models. A reliable end-to-end demo built on SAM 3.1, with Muse Spark used visibly but off the hot path, fits the rubric better than a fragile per-frame VLM loop.
