# hackathon-rules

## SUMMARY
I found the official sources. Meta's event page is dev.meta.ai/events/global-hackathon. The event is run on Cerebral Valley, not Devpost or lablab: applications, a login-gated Participant Guide at /details, and the submission portal at cerebralvalley.ai/e/meta-ai-developer-hackathon/hackathon/submit. The binding Official Rules are titled "Hackathon Terms & Conditions ('Official Rules') and Event Waiver", dated Oct 25, 2026. They are embedded in the Cerebral Valley waiver and event pages. The page renders client-side, so a plain fetch shows "Loading..."; I extracted the text from the raw HTML and the .md version. The rules confirm the judging weights exactly: Impact 30%, Use of Meta AI Tooling 25%, Technical Depth & Execution 20%, Demo 25%. Impact explicitly includes fitting "one of the problem statements", and Demo explicitly includes holding up live and the quality of the demo video. The rules also confirm $150 in Meta Model API credits per selected participant, valid for a 10-day development window. Track prizes are Indie $400K (150/100/75/50/25K) and Startup $550K. Bonus prizes total up to $50K, with categories left to the organizers. The public rules do NOT contain a "new work only" clause. They require original, solely owned work, allow paid third-party technical help, and allow open source if licenses are followed and the project builds on it. They say nothing about pre-event designs, boilerplates or AI coding assistants, though Meta's own Muse Code coding agent is promoted. No public official source gives: demo video length, a public-repo requirement, submission form fields, a testable-build requirement, how judges access a mobile app, named bonus categories (Best Agentic Use-Case / Best Build on Open Weight Models), or the anti-project list. Those items appear only in one participant team's public notes, apparently copied from the login-gated Participant Guide. Those notes say: a 3-minute demo video, a public repo, new work only, a pass/fail gate, and an anti-project list that includes "Simple Image Analyzers". Treat them as likely but confirm them against the team's own guide. Two corrections to the team's beliefs: official judging is listed as Nov 4–Nov 8, not Nov 5–8, and bonus prizes are announced on or about Nov 10. The deadline is Nov 4 9:00 PM ET = 2026-11-05 02:00 UTC = Nov 5 11:00 KST.

## RECOMMENDATION
1. Treat the Official Rules (Cerebral Valley waiver page, dated Oct 25 2026) as the binding contract. Use the team's private Participant Guide (cerebralvalley.ai/e/meta-ai-developer-hackathon/details) for the items that are not public, and settle them there first: video length (reportedly 3 minutes), public-repo requirement, exact new-work wording, submission form fields, and bonus-prize opt-in.

2. Design to the confirmed rubric:
- **Impact (30%):** frame HeyNavi under the 'Build for Your World' theme. State the theme explicitly in the submission, since fitting a theme is reportedly a pass/fail gate.
- **Meta AI Tooling (25%):** go clearly beyond one API call. Combine a Muse Spark/Wonder vision model, SAM 3.1 segmentation and tracking, and Muse Voice Transcribe in one agentic loop, and show something unexpected, such as SAM 3.1 tracking across frames to confirm a find.
- **Demo (25%):** record on the physical iPhone in a real room with real 'find my chair' searches, barge-in, and Korean as well as English. The product must also hold up live for a possible Nov 9 final.
- **Technical Depth (20%):** confirmation across frames, latency handling, and keeping keys server-side.

3. Avoid the 'Simple Image Analyzers' anti-project. Lead with Active Object Search as an autonomous, goal-holding, multi-step agent rather than 'describe this photo'. Scene description and OCR should be supporting features, not the headline.

4. Avoid the medical-advice anti-project. Keep obstacle mentions cautious and non-authoritative, and add a line that HeyNavi does not replace a cane or guide dog.

5. New-work safety:
- Start a fresh public repo now with a dated commit history (the building period started Oct 27).
- Add a README section 'Built during the hackathon', listing any pre-event design notes and open-source libraries with their licenses.
- Disclose use of AI coding assistants. The public rules do not ban them, and Meta promotes Muse Code; using Muse Code for part of the work reads well to judges.

6. Judge access: no public rule asks for TestFlight or an APK. Plan for a public repo, a clear README with run steps (Expo dev build or Expo Go if it works), the demo video, and a hosted backend. Fallback: offer a short live walkthrough or a hosted web build of a reduced flow if the guide asks for a testable build. Do not let TestFlight block the plan, since it would need full Xcode or EAS and an Apple Developer account.

7. Optional bonuses (names from the community notes):
- Best Agentic Use-Case ($5K) fits Active Object Search naturally.
- Best Build on Open Weight Models ($10K) requires Muse Glimmer or Muse Spark Open on your own hardware or partner inference. Consider it only if Baseten, Modal or Fireworks credits are granted, for example as a secondary reasoning path.
- Most Viral ($20K) needs an X post of the demo by Nov 8.

8. Credits:
- Every team member should claim their own $150 Meta Model API credits before Nov 4 9 PM ET and set a spend limit. The rules say the credits are valid for a 10-day window.
- Do not count on partner credits.

9. Submit well before Nov 4 9:00 PM ET (2026-11-05 02:00 UTC). Do not rely on the platform's undocumented 6-hour grace field.

## RISKS
- Anti-project exposure: 'Simple Image Analyzers' (reported list) could catch HeyNavi if the demo looks like describing photos or reading text. The pass/fail gate reportedly disqualifies before any scoring.
- The reported medical-advice anti-project, plus general safety, could be triggered if obstacle warnings are framed as authoritative navigation or safety guidance for blind users.
- Several key items come only from one participant team's public notes, not official public text: anti-projects, named bonus categories, the 3-minute video, public repo, 'new work only', and the pass/fail gate. They may be paraphrased or out of date, so verify each against the private Participant Guide.
- The public rules grant organizers a perpetual, irrevocable license to the Submission and say materials are not confidential. A public repo means no secrets in the repo; Meta API keys must stay in backend env vars that are never committed.
- Fireworks credit amount conflicts ($100 on the public CV page vs $25 for shortlisted teams in the guide notes and two articles). All partner credits are discretionary.
- The Credit Terms PDF was not accessible (HTTP 403, expired signed URL). Credit expiry and which models the $150 covers (SAM 3.1, Muse Voice Transcribe) are unverified. The '10-day development window' may end around Nov 4–5.
- Live-final risk: the Demo criterion scores whether the product holds up live. A physical-iPhone demo depends on network, backend uptime and API latency on Nov 9 if HeyNavi reaches the top 5.
- How judges access a mobile app is unspecified. If the guide requires a testable build, iOS distribution without full Xcode is hard (EAS cloud build and an Apple Developer account would be needed).
- Timezone confusion: some aggregators (Internshala) convert the deadline wrongly by one hour. The platform deadline is 2026-11-05 02:00 UTC.
- The Baseten model ID 'meta-models/muse-spark-open-1026' comes from participant notes and is unverified. Do not hardcode it without checking the Baseten docs or Discord.
