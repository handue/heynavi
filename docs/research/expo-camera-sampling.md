# expo-camera-sampling

## SUMMARY
The current stable Expo release is SDK 58 (released Oct 15, 2026). It ships React Native 0.88 (0.88.1 bundled) and React 19.3.0. The New Architecture has been mandatory since SDK 55, and Expo Go for SDK 58 has been on the App Store since Oct 22. The simplest reliable way to sample frames is expo-camera's CameraView with a serial loop: takePictureAsync({pictureRef:true, shutterSound:false}), then expo-image-manipulator's contextual API, which accepts the PictureRef directly, resizes to about 768 px, fixes EXIF orientation and returns a JPEG with base64. This works in Expo Go and also in a dev build. Set the pictureSize prop to a small preset such as "1280x720", and set animateShutter={false}, because SDK 58 brought back the iOS shutter flash. The biggest risk is the shutter sound. expo-camera mutes it with an old workaround, and Apple says muting is impossible in places that require the sound (Japan and South Korea, apparently decided by the SIM). On a Korean iPhone, a 1–2 s capture loop would then click on every frame, which is bad for a blind user who relies on audio. The silent fallback is VisionCamera v5 (5.2.4, Nitro-based). It needs a dev build: frame output, then HybridFrameConverter.convertFrameToImage, then nitro-image resize and JPEG encode. VisionCamera v5's takeSnapshot works on Android only, and v5 has several open iOS crash issues. For builds, EAS cannot produce a build that installs on an iPhone without the paid $99 Apple Developer Program. With a free Apple ID, the only route is a local Xcode build. On this Mac that is harder than it looks: Xcode 27.x needs macOS 26.6 or later, and the Mac runs 26.4. So either download Xcode 26.6 (works on macOS 26.2 and later, installs to devices on iOS 15 and later, meets SDK 58's Xcode 26.4 minimum) or update macOS first. Then run `brew install cocoapods`, sign Xcode into a free Personal Team, turn on Developer Mode on the iPhone, and run `npx expo run:ios --device`. A free-team build expires after 7 days. Judges realistically cannot install the app without TestFlight, which needs the paid program, and Expo Go only loads EAS Updates for the project's owner or members of its organization (since May 12, 2026). Plan on a demo video.

## RECOMMENDATION
FRAME SAMPLING, primary path (works in Expo Go and in a dev build):
- Use Expo SDK 58. `npx create-expo-app@latest` (template 58.0.30) creates it.
- Render one `<CameraView>` that stays mounted, with `pictureSize="1280x720"` (or "1920x1080" if small objects get missed) and `animateShutter={false}`. Wait for `onCameraReady`. Keep the tree around it stable: no conditional siblings rendered before it, because of expo/expo #50015.
- Run a serial loop rather than setInterval. Each pass does:
  - `const ref = await cam.takePictureAsync({ pictureRef: true, shutterSound: false, quality: 0.8 })`
  - `const img = await ImageManipulator.manipulate(ref).resize({ width: 768 }).renderAsync()` (for portrait, resize by height or by the long edge)
  - `const out = await img.saveAsync({ format: SaveFormat.JPEG, compress: 0.6, base64: true })`
  - call `ref.release()` and `img.release()`, and delete `out.uri` with expo-file-system
  - upload the base64 (or the file through FormData) to FastAPI
  - wait 1000–1500 ms minus the elapsed time, then repeat
- Keep at most one capture and one request in flight, and drop results that arrive after the goal changed.
- On the backend, also apply PIL `ImageOps.exif_transpose` as a safety net for orientation.
- Confirm a detection across 2–3 consecutive frames before speaking.

Day-1 checks on the actual iPhone: listen for a shutter click, and measure capture-to-JPEG time.

SILENT FALLBACK (dev build only), if a click is audible (likely on a Korean or Japanese SIM or device) or latency is poor:
- Use VisionCamera 5.2.x with react-native-nitro-modules, react-native-nitro-image, react-native-vision-camera-worklets and react-native-worklets 0.13.x.
- Set `useFrameOutput({ targetResolution: {width:1280,height:720}, dropFramesWhileBusy: true, onFrame })`. In the worklet, check `frame.timestamp` and process only one frame every ~1.5 s. Everything else gets `frame.dispose()` immediately.
- For the chosen frame, use `asyncRunner.runAsync(() => { const im = HybridFrameConverter.convertFrameToImage(frame); frame.dispose(); const jpg = im.resize(768, 432).toEncodedImageData('jpg', 70); scheduleOnRN(upload, jpg.buffer) })`. Rotate as needed.
- Wrap all worklet code in try/catch because of VisionCamera #4219, and pin exact versions.
- Do not rely on VisionCamera takeSnapshot: in v5 it works on Android only.

BUILD PATH, starting with no Xcode:
1. Start the Xcode download now. On macOS 26.4, the App Store's Xcode 27.x will not install (it needs macOS 26.6+). The user should sign in at developer.apple.com/download/all and download Xcode 26.6 (.xip, about 2–3 GB), or update macOS to 26.6+ and install Xcode 27.1 from the App Store.
2. While it downloads, build the camera, TTS and backend loop in store Expo Go (SDK 58, logged in on both the CLI and the app). For speech-to-text in Expo Go, record with expo-audio and transcribe on the server.
3. After Xcode installs: open it once, `sudo xcode-select -s /Applications/Xcode.app`, run `brew install cocoapods`, and add the Apple ID under Xcode > Settings > Accounts (creates the Personal Team).
4. In the project: `npx expo install expo-dev-client`, then set a unique `ios.bundleIdentifier`. Keep it fixed, because of the 10 App IDs per 7 days limit. Avoid entitlements a Personal Team cannot sign, such as push notifications.
5. Plug in the iPhone, trust the Mac, and turn on Developer Mode. Run `npx expo run:ios --device`; if signing fails, set the Personal Team in ios/*.xcworkspace. Then trust the developer under Settings > General > VPN & Device Management.
6. Iterate on JS with `npx expo start --dev-client`. Rebuild at least every 7 days, and before judging.

Only pay $99 for the Apple Developer Program if judges must install the app (TestFlight or EAS internal distribution). Otherwise submit a demo video and the repo.

## RISKS
- The iOS shutter sound may play on every 1–2 s capture with expo-camera on iPhones with a Korean or Japanese SIM or region. Apple disallows suppression in those jurisdictions, and expo-camera uses only a legacy workaround. This would badly hurt a blind user's audio experience.
- Captured JPEGs carry EXIF orientation with unrotated pixels (expo-camera 58.0.0 change). If raw captures go to the model without the manipulator or an EXIF transpose, images may arrive sideways.
- The mismatch between macOS 26.4 and Xcode 27 can cost hours if the user tries the App Store first. Updating macOS mid-hackathon has its own risk.
- Free Personal Team builds expire after 7 days, with limits of 3 devices, 10 App IDs and 3 apps per device. A build made Oct 29–30 could stop launching before judging, so rebuild close to the deadline.
- VisionCamera v5 has open iOS crash issues (#4209, #4211, #4219). Nobody has confirmed it builds on RN 0.88 / SDK 58, so the silent fallback may need debugging time.
- expo-camera issue #50015 (closed without a fix): re-parenting CameraView under the New Architecture can crash the next takePictureAsync with 'No active and enabled video connection'.
- Cache file buildup: saveAsync always writes a file, and takePictureAsync without pictureRef writes one too. Delete files after upload. Uncollected native refs can also grow memory if release() is not called.
- Expo Go store builds now support only one SDK (58), require a login in both the CLI and the app, and load EAS Updates only for owners or organization members. Judges cannot simply open a link.
- expo-speech-recognition does not work in Expo Go and has not yet listed SDK 58 in its compatibility table. It also switches the iOS audio session to playAndRecord, which can interact with TTS and barge-in.
- No published latency numbers exist for expo-camera capture on iPhone. The 1–2 s cadence plus the model round-trip has to be measured on the device.

## VERIFIER MISSED
- Shutter sound is probably the deciding factor, not an edge case. iPhones with a Korean or Japanese region or SIM always play the shutter sound, so check the test phone first. A one-minute check settles it before any code: set the Ring/Silent switch to silent and take a photo in the built-in Camera app. If it clicks, expo-camera's takePictureAsync loop will click on every frame, and so will VisionCamera v5 capturePhoto, which only uses the iOS 18 suppression API when supported and has no fallback. The only silent native path is then video-data-output frames: VisionCamera useFrameOutput or a custom module. Both need a dev build, so the Xcode download is on the critical path from today.
- Concurrent captures throw. expo-camera iOS rejects takePictureAsync with CameraNotReadyException while another capture is in flight. Object search, 'describe scene' and 'read text' must share one serialized capture queue, or the user-triggered commands will fail at random during a search.
- Crop to preview aspect. expo-camera crops every capture to the preview layer's aspect ratio. A full-screen portrait CameraView over a 16:9 '1280x720' capture loses about 18% of the horizontal field of view, which hurts object coverage and left/right localization. Size the CameraView to the capture aspect (9:16 portrait for 16:9 presets, 3:4 for 'Photo' or '640x480'). A blind user does not need a full-screen preview.
- Screen auto-lock in release builds. Expo keeps the screen awake only in __DEV__: withDevTools calls useKeepAwake, and that code is tree-shaken from production builds. A release or demo build will auto-lock during a long 'find my chair' search and stop the camera. Call useKeepAwake or activateKeepAwakeAsync (expo-keep-awake, included in Expo Go) while a search or the camera is active.
- TTS and the silent switch. With the default app audio session, expo-speech (AVSpeechSynthesizer, useApplicationAudioSession default) is muted by the Ring/Silent switch, which is the same switch the researcher relies on to mute the shutter outside JP/KR. Set an audio mode that plays in silent mode (expo-audio), then re-test whether the shutter click comes back. The barge-in path (recording while speaking) also needs playAndRecord with defaultToSpeaker, or TTS goes to the earpiece.
- Precompiled XCFrameworks and Xcode 26.6. Since SDK 56, Expo ships prebuilt iOS XCFrameworks by default for local builds too. No source confirms they import cleanly with Xcode 26.6 if they were built with Xcode 27. If `npx expo run:ios` fails with Swift module or interface errors, rebuild with EXPO_USE_PRECOMPILED_MODULES=0 (or expo-build-properties ios.usePrecompiledModules:false), which is slower but builds from source.
- A silent, no-Xcode, judge-accessible fallback was not considered: an Expo web build served over HTTPS and opened in iOS Safari. expo-camera's web takePictureAsync draws the <video> frame to a canvas (WebCameraUtils), so there is no shutter sound, and it has a web-only `scale` option for downscaling. Deploy with `npx expo export -p web` and `eas deploy`. Caveats: getUserMedia needs HTTPS, speechSynthesis and audio need a user gesture first, Safari may pause the camera in the background, and web speech recognition support is limited (record audio and transcribe on the backend instead). It keeps the same React Native and Expo codebase and gives judges a URL.
- A lighter alternative to VisionCamera v5 for silent frames: a local Expo module (`npx create-expo-module@latest --local`) wrapping AVCaptureVideoDataOutput that returns a downscaled JPEG on demand. It avoids Nitro, worklets and the open v5 crash issues, but you have to own the capture session and preview, so it is only worth it if v5 fails to build on RN 0.88.
- VisionCamera 5.2.4 was published today (2026-10-29 08:59 UTC). The open crash reports are against 5.2.3. Pin one exact version and smoke-test it on device before depending on it. SDK 58 pins react-native-worklets 0.13.0 while npm latest is 0.13.1. Use `npx expo install` so it matches.
- expo-camera 58.0.12 made the multi-lens back camera the default on macro-capable iPhones, so the active lens and field of view can switch automatically between frames, for example at close range. If detections flicker, set selectedLens to the wide camera.
- Expo's own local-device guide tells users to install Xcode from the Mac App Store and use 'Device Hub'. On macOS 26.4 neither works: App Store Xcode 27 requires 26.6+, and Device Hub is new in Xcode 27. Following the guide literally wastes hours.
- Account steps the user must do personally: create or sign in to the same Expo account in both the CLI and Expo Go (required since Sep 3, 2026), sign in at developer.apple.com and accept the developer agreement to download the Xcode 26.6 .xip, and add the Apple ID in Xcode for the Personal Team.
