# sam-3-1

## SUMMARY
SAM 3 came out on 2025-11-19. It does promptable concept segmentation: you give it a short noun phrase such as "chair", image exemplars, or points/boxes/masks, and it returns a box, mask and score for every matching instance. SAM 3.1 (2026-03-27) adds Object Multiplex, a shared memory for tracking many objects at once, and its published speedups are for video tracking only. Meta published nothing on single-image speed for 3.1. The most useful finding for HeyNavi is that Meta already hosts SAM 3.1 on the Meta Model API as model `sam-3.1`, on the same OpenAI-compatible `POST https://api.meta.ai/v1/responses` endpoint and bearer key as the Muse models. It accepts a base64 data-URL image and costs $2.50 per 1,000 images, so the $150 hackathon credit buys about 60,000 frames. The rate limit is 3,000 RPM per team, and there is no GPU to manage. Its output is not JSON but a special-token text format (`<0f>0<|box;x1=..;y1=..;x2=..;y2=..;w=..;h=..;c=..|><|mask;...|>`), and zero matches come back as an empty output_text. Meta publishes a zero-dependency Python parser (`meta-sam-parser`) for it. Meta publishes no latency figure for the hosted endpoint, so the 1.5 s budget is plausible but has to be measured on day 1. The published model-side numbers are 30 ms per image (100+ objects, H200, from the paper) and 251.4 ms on one L4 (Roboflow, single text prompt). Self-hosting is possible through transformers `Sam3Model`/`Sam3Processor`, but only for SAM 3 (`facebook/sam3`, gated). SAM 3.1 checkpoints have no transformers integration, and the official repo needs a CUDA 12.6+ GPU. I found no published Apple Silicon timings, and MPS support is still in open PRs, so the Mac is not a viable runtime. Muse Spark 1.3 has documented visual grounding (boxes/points on a 0-1000 normalized grid) on the same API, which makes it a zero-setup fallback. Its weak spot is presence: a VLM may report or box an object that isn't there. That is why confirmation across frames matters.

## RECOMMENDATION
PRIMARY (verified to exist; latency not verified): use Meta's hosted `sam-3.1` through the existing FastAPI backend, with no GPU to provision.
(1) The iPhone captures a frame, resizes it on-device to 640-1024 px on the long side, encodes it as JPEG q≈0.7, and POSTs it to FastAPI.
(2) FastAPI forwards it to POST https://api.meta.ai/v1/responses with model 'sam-3.1', an input_text noun phrase ('chair'), input_image as a base64 data URL, metadata {include_confidence:'true', mask_encoding:'one_bit'} and stream:false. It reuses one keep-alive httpx/OpenAI client.
(3) Parse with `meta-sam-parser`, keep only boxes with c, and ignore masks. An empty output_text means 'not seen in this frame'.
(4) Turn the user's utterance into one English noun phrase before calling SAM: 'find my chair' / '내 의자 찾아줘' → 'chair'. Use a regex for common objects and a cheap muse-spark call otherwise. That SAM's text prompts must be English is inferred, not verified.
(5) Confirm across frames: announce only after, e.g., 2 of the last 3 frames return the concept with c ≥ ~0.5 (tune this threshold). Direction comes from the box centre: x/w < 0.33 'left', > 0.67 'right', else 'ahead'. Box area / frame area gives a rough 'close/far'.
(6) Cost is $2.50 per 1,000 frames (about $9 per hour at 1 fps). Pause the loop when the app is backgrounded or the goal is satisfied.
Do this on day 1: get an API key, send 20 real 768 px frames, and log p50/p95 round-trip from FastAPI and from the phone. Meta publishes no latency, so the <1.5 s target is INFERRED from the 30 ms H200 and 251 ms L4 model-side numbers plus network overhead.

FALLBACK A (zero extra setup, verified docs): Muse Spark 1.3 grounding on the same key. Prompt 'You are an object grounding expert… return JSON {present: bool, bbox: [x_min,y_min,x_max,y_max] on a 0-1000 grid}' with structured output, then scale by the image size and clamp. This works for 'find my chair', but VLMs can claim objects that are not there, so require multi-frame agreement and phrase results cautiously ('I think I see…'). You can also use Spark as a verifier on the frame where SAM first fires.

FALLBACK B (minutes of setup): Roboflow Serverless `sam3/concept_segment` (251 ms published on an L4; pricing unverified), or fal.ai `fal-ai/sam-3/image` ($0.005/request; latency unknown). Keep the backend's SAM client behind an interface with providers meta_sam31 | muse_grounding | roboflow, so you can switch providers with an env var.

FALLBACK C (most effort, about half a day): self-host SAM 3 (not 3.1) on Modal with transformers Sam3Model + facebook/sam3. Request HF gated access today. Use an L4 or A10 (inferred sufficient; the L4 is $0.80/h), bake the weights into the image or a Volume, load them in @modal.enter, precompute the text embedding per goal, and expose a FastAPI endpoint taking {image_base64, prompt}. Deploy with min_containers=0 and scaledown_window of about 600-1200 s. Before a test or demo session, run a script that calls `obj.method.autoscaler.update(min_containers=1)` and sends one warm-up request. Afterwards, set min_containers back to 0, or use a modal.Cron pair around the demo slot. Three hours of warm L4 is about $2.40, inside the $30 Starter credit.

Do NOT plan on running SAM 3 on the M-series Mac. There is no verified usable speed, MPS support sits in unmerged PRs, and the official repo needs Triton/CUDA. Muse Spark Open/Glimmer are self-host only and irrelevant here.

## RISKS
- Hosted sam-3.1 latency is undocumented. The phone-to-FastAPI-to-Meta round trip, plus base64 upload of a 768-1024 px JPEG, could exceed 1.5 s, especially on mobile networks or if the FastAPI server is on the Mac behind a tunnel.
- No image size or file-size limit is documented for sam-3.1. Oversized frames could be rejected or slow, so downscale on-device.
- The sam-3.1 response always includes a mask per object (no boxes-only mode), which inflates payload and parse time. Use mask_encoding 'one_bit' and discard masks.
- There is no server-side confidence threshold. False positives must be filtered client-side using `c` (requires include_confidence='true' and meta-sam-parser >=0.0.6) and multi-frame confirmation.
- Meta's docs say 'commands, questions, lists, negation, and spatial phrasing' are unreliable as prompts. Raw utterances like 'find my chair' or Korean text must be normalized to a single English noun phrase first (English-only is inferred).
- Hackathon credits may not cover sam-3.1, or may be limited to certain models (unverified). The 3,000 RPM limit is per team and shared with any other Meta API calls.
- VLM-only grounding (Muse Spark) can hallucinate presence or return loose boxes. For a blind user, a false 'found it' is worse than a slow answer, so phrase results cautiously and confirm across frames.
- Self-hosting needs gated HF approval for facebook/sam3 with unknown turnaround. SAM 3.1 weights have no transformers integration, and the official repo needs CUDA 12.6+ and Triton.
- Cold starts on Modal or HF endpoints (loading about 3.5 GB of weights) can take tens of seconds to minutes. Warm the container before demos, or the first query will blow the latency budget.
- Community-hosted SAM 3 models on Replicate are unofficial and may cold-boot (e.g. a T4 version 'within 8 seconds'), so they are unsuitable for the live loop.
- Fireworks and Baseten have no turnkey SAM; time spent there would be custom deployment work.
- The SAM License bars military/ITAR use and requires passing the license on with redistribution. Fine for HeyNavi, but note it in the submission if weights are redistributed.

## FINDINGS
- [S1|verified] SAM 3 was announced 2025-11-19. It is a unified model that detects, segments and tracks objects in images and video from concept prompts: short noun phrases (e.g. 'yellow school bus'), image exemplars, or both, plus SAM-style points, boxes and masks. It returns masks and unique IDs for ALL matching instances. Architecture: a DETR-based image detector and a SAM2-style memory tracker that share one vision encoder, about 848M parameters (the HF card shows 0.9B, F32). A presence head decouples recognition from localization: each query's final score is its own score multiplied by a global presence score. (notes: transformers exposes presence_logits; per the docs, final_scores = pred_logits.sigmoid() * presence_logits.sigmoid().) || VERIFY: confirmed — Minor: the paper appendix gives about 850M parameters (450M vision encoder, 300M text encoder, 100M detector and tracker). The HF card shows 0.9B F32. The presence-score product is confirmed in both the paper and the transformers docs (final_scores = pred_logits.sigmoid() * presence_logits.sigmoid()). The paper also says the input is always a fixed square, usually 1008x1008, and the text encoder's max context length is 32.
- [S2|verified] SAM 3.1 ('Object Multiplex') was released 2026-03-27. ## VERIFIER MISSED
- Rate limits are per team AND per model ('Each model has its own limits'). sam-3.1's 3,000 RPM is independent of muse-spark-1.3's 3,000 RPM, so running SAM per frame and Spark for verification or description does not contend for one budget (https://dev.meta.ai/docs/pricing-rate-limits).
- There is no iPhone on-device fallback in this setup. Without full Xcode or EAS, the app runs in Expo Go, which cannot load custom native modules (CoreML, Vision, frame processors). expo-camera is in Expo Go but has no per-frame video access, only takePictureAsync (https://docs.expo.dev/versions/latest/sdk/camera/). All detection must be server-side, which makes the hosted sam-3.1 latency gate even more critical.
- Frame capture settings affect both latency and correctness. takePictureAsync has shutterSound (default true), which must be set false so a shutter click does not fire every 1-2 s over TTS; iOS behaviour needs verifying on the device. Also set animateShutter false. skipProcessing:true is faster but 'skips orientation adjustment' and ignores quality. Rotated frames would flip the left/right announcements for a blind user. Normalize orientation (keep processing, or re-encode via an image manipulator), and assert that the w/h in the returned box token match the upright frame before computing direction.
- SAM 3's model input is always a fixed square, usually 1008x1008 (paper). Uploading much more than ~1008 px on the long side wastes bandwidth, while 640 px may lose small or distant objects. How the hosted endpoint resizes and pads is undocumented, so test 768 vs 1008.
- JPEG input is not explicitly documented for sam-3.1 (the docs example uses data:image/png). Confirm that JPEG data URLs work on day 1; PNG frames would be several times larger to upload.
- Python parsing: meta-sam-parser documents only build_object_prompt and decode_mask_* for Python, and no Python line or stream parser is shown. For HeyNavi you need boxes only, so a regex over `<|box;x1=..;y1=..;x2=..;y2=..;w=..;h=..;c=..|>` tokens (fields parsed by key, since c position varies) is simpler and avoids decoding masks. Use non-streaming for single images.
- Per-image requests carry no cross-frame identity; stable object IDs exist only within one video request. Multi-frame confirmation must match detections by box centre or IoU across frames, not by ID. The docs also say outputs 'can vary slightly between runs of the same request'.
- 'Find my chair' returns EVERY chair. SAM has no notion of ownership or a specific personal instance. The app must handle multiple instances: announce the count plus the nearest/largest, or the one closest to centre ('I see two chairs; the closest is on your left'). Strip possessives and verbs before prompting, since commands and questions 'often return nothing'.
- A video-mode alternative was not considered. Sending a 1-2 s MP4/MOV clip gives tracked objects with stable IDs (up to 16) in one call, which is native temporal confirmation. The cost is $0.01 minimum per request (50-frame minimum) vs $0.0025 per image, plus clip encode and upload latency. Probably not worth it for the loop, but it is an option for a confirm step.
- Muse Spark cannot turn reasoning off ('none' returns HTTP 400). Use reasoning.effort 'minimal' for any grounding or verification call. Expect Spark latency well above SAM's, so Fallback A is better as a one-shot verifier or a description call than as the 1-2 s per-frame loop (https://dev.meta.ai/docs/reasoning).
- Account and region gating risk: a Meta community forum thread (Oct 24, 2026) reports 'The Model API isn't available in your region right now', and Meta's docs list no supported countries. The hackathon is open worldwide except sanctioned countries, but confirm on day 1 that the key works from the developer's actual location and that sam-3.1 is enabled for the account.
- Credits: the official hackathon page does not state the $150 amount or which models it covers, though it names SAM 3.1 as a model to use via the Meta Model API. Check the dashboard balance before relying on the 60k-frame estimate (https://dev.meta.ai/events/global-hackathon).
- Privacy: the muse-spark-*-contributor variants are ~10-20x cheaper but are 150 RPM and allow Meta to train on submitted content. Do not use them for camera frames from a blind user's home; stay on Standard mode. No contributor variant is listed for sam-3.1.
- Muse Voice Transcribe is speech-to-text only, and the models page says it has 'No speech synthesis'. TTS for the 'I found a chair' announcement must therefore be on-device (e.g. expo-speech) or come from another provider, which affects the barge-in design.
- The Modal autoscaler.update(min_containers=1) override reverts on the next deploy, so a redeploy during demo prep silently re-enables cold starts (https://modal.com/docs/guide/scale).

## VERIFIER REVISED RECOMMENDATION
Keep hosted `sam-3.1` on the Meta Model API as the primary detector, but gate it on day 1 (2026-10-29/30).

Day-1 gate (about 1 hour):
(a) A key from the dev.meta.ai dashboard works from the developer's location, and sam-3.1 is enabled. Check that the hackathon credit balance appears and applies to it.
(b) A JPEG base64 data URL is accepted. If not, fall back to PNG.
(c) Measure p50/p95 for 20 real frames at 768 and 1008 px long side, from FastAPI and from the phone. Use non-streaming requests with metadata {include_confidence:'true', mask_encoding:'one_bit'}.
(d) Verify that the returned w/h match the upright frame dimensions.
If the gate fails on access, move to Roboflow Serverless or fal-ai/sam-3/image behind the same interface. Their hosted latency is also unknown (Roboflow's 251 ms is self-hosted), so measure those too.

Pipeline:
- On the phone, use expo-camera takePictureAsync with shutterSound:false and animateShutter:false. Keep orientation processing on, or bake orientation in when re-encoding to JPEG q≈0.7 at ~768-1008 px.
- Run at most one request in flight per goal, and capture the next frame while the previous call is outstanding.
- FastAPI normalizes the utterance to one English singular noun phrase. Strip 'find', 'my', 'where is' and questions; translate Korean via a regex/lexicon first and a muse-spark-1.3 call at reasoning.effort 'minimal' otherwise. Use Standard mode, not contributor.
- Call sam-3.1 through one keep-alive client. Parse only the `<|box;...|>` tokens with a key-based regex and ignore masks. An empty output_text means not seen.
- Confirm by spatial agreement: same concept with c ≥ ~0.5 in 2 of the last 3 frames, with box centres or IoU consistent. Per-image calls have no stable IDs.
- When several instances are returned, announce the count and the nearest/largest one. Direction comes from the box centre (thirds), and rough distance from box-area fraction.
- Phrase announcements cautiously, and stop the loop when the goal is met or the app is backgrounded.

Cost: about $0.0025 per frame, roughly $9 per active hour at 1 fps. sam-3.1's 3,000 RPM is separate from Muse Spark's.

Optional verifier: on the first confirmed hit, send one muse-spark-1.3 grounding call (reasoning.effort 'minimal', structured output, bbox as [{x_min,y_min,x_max,y_max}] on a 0-1000 grid, absent objects omitted) to cut false positives. Do not use Spark as the per-frame loop, since its latency is likely too high.

Drop self-hosting (Fallback C) unless the gate fails and no hosted SAM works. Expo Go also rules out on-device ML, and the Mac is too slow: published community timings show ~2 s per frame just for the SAM 3.1 backbone on an M-series laptop. If Modal is used anyway, remember that autoscaler overrides revert on redeploy.
